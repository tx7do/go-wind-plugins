# Go-Wind 插件教程 · 第 18 章：AI 大模型集成

> 本篇是 [Go-Wind 插件教程系列](./README.md)的组成部分。AI 家族的三个模块直接返回各框架的原生客户端类型——三家 SDK 的返回类型互不兼容，本层不定义统一对话接口，只提供共享的 `ai.Config` 配置类型。

## 1. 构造面

| 输入 | 构造函数 | 返回 |
|-------|-------------|---------|
| `ai.Config` | `model.NewClient(cfg)` | `*openai.Client` |
| `ai.Config` | `eino.NewChatModel(ctx, cfg)` | `model.ChatModel`（Eino 接口） |
| `ai.Config` | `langchaingo.NewModel(cfg)` | `llms.Model`（LangChainGo 接口） |

`ai.Config` 统一承载 API 端点、密钥、模型名等参数——同一份配置在三个框架间可复用，切换框架只换构造函数调用点。

## 2. 插件矩阵

| 插件 | 模块路径 | 框架 |
|------|---------|------|
| OpenAI | `github.com/tx7do/go-wind-plugins/ai/openai` | sashabaranov/go-openai |
| LangChainGo | `github.com/tx7do/go-wind-plugins/ai/langchaingo` | tmc/langchaingo |
| Eino | `github.com/tx7do/go-wind-plugins/ai/eino` | cloudwego/eino |

## 3. 三家框架的能力取向

- **[OpenAI](../../ai/openai/README.md)**：直连 OpenAI 兼容端点——云端模型与**本地模型（Ollama）**两种接入形态，Chat Completion 调用示例在文档中逐一直给。适合只需要对话补全、不需要编排的轻量集成。
- **[LangChainGo](../../ai/langchaingo/README.md)**：链式编排生态——Model 之外提供 Agent（工具调用自治）、Chain（管道）、Memory（会话记忆）三件套的 Go 移植。适合检索增强、多步推理这类需要组装的玩法。
- **[Eino](../../ai/eino/README.md)**：CloudWeather 出品的编排框架——ChatModel 之外是 Chain / Graph 编排、Prompt 模板与 Tool（函数调用）体系，其类型化的图编排与回调体系面向生产级可控链路。

与 MCP 的配合：[`transport/mcp`](../../transport/mcp/)（[第 8 章](./08-transport-middleware.md)矩阵）提供 Model Context Protocol 服务器，可把自有工具能力按 MCP 暴露给支持该协议的模型端。

## 4. 接入要点

- `ai.Config` 里的密钥经[第 1 章](./01-config.md)的配置层注入（云厂商密钥放 `config/vault`）。
- 本地推理（Ollama 端点）适合开发调试与数据不出域场景，生产吞吐规划要区分「本地小模型」与「云端大模型」两条成本曲线。
- 面向终端用户的 AI 功能要在入口层（[第 9 章](./09-resilience.md)限流、[第 4 章](./04-metrics.md)按 token 用量打点）做成本护栏——LLM 调用的单次成本比传统请求高数个量级。
