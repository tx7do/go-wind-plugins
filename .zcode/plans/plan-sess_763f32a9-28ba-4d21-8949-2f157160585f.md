# 集成 kratos-swagger-ui 到 go-wind-plugins

## 结论先行
go-wind-plugins **目前没有任何 swagger 代码**（全局 grep 零命中）。按你的选择，新建独立子模块 `transport/http/swagger`，把 kratos-swagger-ui 的核心逻辑移植进来，沿用其依赖 `swaggest/swgui v1.8.5` + `vearutop/statigz v1.5.0`。

## 需要先解决的一个障碍
go-wind 的 `Driver` 接口（`transport/http/server.go:20`）当前只有 `Handle(method, path, http.HandlerFunc)`，**没有前缀挂载能力**。而 swagger UI 必须前缀挂载——静态资源是 `/docs/swagger-ui-bundle.js` 这类动态子路径，且要支持本地 openapi.json / 内存数据源等子路由。

因此第一步是给 `Server` 和 3 个 driver 补 `HandlePrefix`。

---

## 改动清单（按依赖顺序）

### 第一部分：给 Driver / Server 补 HandlePrefix 能力

**1. `transport/http/server.go`** — 扩展 Driver 接口 + 给 Server 加方法
- `Driver` 接口新增 `HandlePrefix(prefix string, h http.Handler)` 方法
- `Server` 新增 `HandlePrefix(prefix string, h http.Handler)` 方法：转发到 driver，**不套中间件链**（swagger 静态资源是纯文件服务，套业务中间件无意义且有性能开销，与 kratos 原生 `HandlePrefix` 语义一致）

**2. `transport/http/driver/std/std.go`** — 实现 HandlePrefix
- `d.mux.Handle(prefix, h)`，net/http 的 ServeMux 天然支持前缀匹配（`/docs/` 结尾的 pattern）

**3. `transport/http/driver/gin/gin_driver.go`** — 实现 HandlePrefix
- gin 用 `d.engine.Any(prefix+"*filepath", gin.WrapH(h))` + 内部 stripPrefix 包装
- 注意 gin 的 `*filepath` 通配符 + `c.Request.URL.Path` 的 strip 逻辑

**4. `transport/http/driver/fiber/fiber_driver.go`** — 实现 HandlePrefix
- fiber 用 `d.app.Use(prefix+"/*", adaptHandler(h))` 或 `d.app.Add("/*", ...)` 形式
- 经适配层（已有 adaptFiber 逻辑，复用 sync.Pool 的 responseWriter）

> 注：这三个 driver 的改动是**纯增量**（新增方法，不改动现有 Handle 路径），不影响现有用户和 benchmark。

### 第二部分：新建 swagger 子模块

**目录**：`transport/http/swagger/`（单模块，module path `github.com/tx7do/go-wind-plugins/transport/http/swagger`）

**移植文件**（从 kratos-swagger-ui 改包名 + 适配 go-wind）：
| 新文件 | 来源 | 改动 |
|---|---|---|
| `handler.go` | `internal/swagger/handler.go` | package 改 `swagger`，逻辑不变 |
| `options.go` | `internal/swagger/options.go` | package 改 `swagger`，`Config` 结构不变 |
| `index_tpl.go` | `internal/swagger/index.tpl.go` | package 改 `swagger`，模板不变 |
| `embedded.go` | `kratos-swagger-ui/embedded.go` | package 改 `swagger`，依赖 `swaggest/swgui/v5/static` + `statigz` |
| `file_handler.go` | `kratos-swagger-ui/file_handler.go` | package 改 `swagger`，openapi 文件/内存数据 handler |
| `swagger.go` | 新写 | 暴露 `New()` / `NewHandler(opts...)` + 对接 go-wind `*http.Server` 的 `Register(srv, opts...)` |

**关键适配点**：kratos 原版的 `RegisterSwaggerUIServer[T httpServerInterface]` 依赖 `srv.HandlePrefix(...)`。移植后，`swagger.go` 提供一个直接接收 go-wind `*http.Server` 的注册函数：

```go
// Register 把 Swagger UI 挂到 go-wind 的 *http.Server 上。
// 等价于 srv.HandlePrefix(basePath, handler)，并把本地/内存 openapi 子路由也注册进去。
func Register(srv *httpPlugin.Server, opts ...Option) *Handler
```

**go.mod**（`transport/http/swagger/go.mod`）：
```

go 1.26.3

    github.com/swaggest/swgui v1.8.5

    github.com/vearutop/statigz v1.5.0
)
replace github.com/tx7do/go-wind-plugins/transport/http => ../..
```

## 不做的事 / 边界
- **不改**现有 `Handle` 路径的任何行为，三个 driver 的 HandlePrefix 是纯新增
- **不引**测试框架之外的新依赖；swgui/statigz 是 swagger 模块独占，不污染 transport/http 主模块的 go.mod
- **不删** kratos-swagger-ui 仓库（那是独立项目，本次只是移植逻辑）
- swagger UI 静态资源由 swgui 通过 embed.FS 提供，**无需**在本仓库单独 vendoring 前端文件

## 验证
- `go build ./transport/http/...` 全绿
- `go build ./transport/http/swagger` 单独构建通过
- `go vet ./transport/http/swagger`
- 跑 `_examples/swagger-basic`，`curl http://localhost:8080/docs/` 返回 swagger UI HTML，`/docs/swagger-ui-bundle.js` 返回 200
- 三个 driver 各自 `go build` 通过，不破坏现有 `*_test.go` 和 benchmark

## 风险
1. **gin/fiber 的前缀路由匹配规则差异**：gin 的 `*filepath` 和 fiber 的 `/*` 通配符语义不完全等同 net/http 的 `/prefix/`。实现时会用各自框架的惯用法 + stripPrefix，并在 example 里实测 std driver（最稳）为主验证路径。如果你只主要用 std driver，这点风险最低。
2. swgui v1.8.5 vs 缓存里的 v1.8.7：默认沿用 kratos 原版的 v1.8.5 以保证行为一致；如你想要最新可改 v1.8.7。
